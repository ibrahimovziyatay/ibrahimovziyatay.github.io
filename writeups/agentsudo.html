00

Giriş

Bu yazı TryHackMe platformasındakı Agent Sudo otağının həllini addım-addım izah edir. Otaq dəniz altında yerləşən gizli bir server haqqındadır və məqsəd həmin serverə daxil olub, içindəki "həqiqəti" üzə çıxarmaqdır.

Otaq boyunca enumeration, HTTP başlığı manipulyasiyası, FTP-yə brute-force, steqanoqrafiya (şəkil içində gizlədilmiş fayllar) və nəhayət sudo-da olan bir zəiflikdən (CVE-2019-14287) istifadə edərək root əldə etmək tələb olunur. Aşağıda proses zamanı çəkdiyim skrinşotlar və hər addımda nə etdiyimin izahı var.

01

Enumeration — Nmap ilə port skan

İlk addım olaraq hədəf maşının açıq portlarını və üzərində işləyən servisləri öyrənmək üçün nmap ilə skan etdim:

nmap -sV -sC -oN nmap_initial.txt <target-ip>

Nəticədə FTP (21), SSH (22) və HTTP (80) portlarının açıq olduğunu gördüm. HTTP portu üzərindən veb tərəfə keçdim.

02

Web Enumeration — User-Agent manipulyasiyası

Hədəfin IP ünvanını brauzerdə açdıqda səhifədə mənim istifadəçi-agentimlə (User-Agent) bağlı bir mesaj gördüm — sanki server konkret bir User-Agent dəyəri gözləyirdi.

Bunu sınamaq üçün sorğunu Burp Suite ilə tutdum (Proxy tabı) və Repeater bölməsinə göndərdim. Sonra HTTP sorğusundakı User-Agent başlığını dəyişib yenidən göndərdim:

Düzgün dəyəri göndərdikdən sonra səhifə "Follow redirection" düyməsi ilə yeni bir cavab qaytardı. Ora keçdikdə isə serverdə işləyən agentlərdən birinin adını — chris — öyrəndim.

03

FTP-yə Brute-Force (Hydra)

"chris" istifadəçisinin FTP parolunu tapmaq üçün Hydra ilə lüğət hücumu (dictionary attack) həyata keçirdim:

hydra -l chris -P /usr/share/wordlists/rockyou.txt ftp://<target-ip>

Parolu tapdıqdan sonra FTP-yə chris hesabı ilə daxil oldum və serverdə olan faylları (şəkillər) yerli maşına endirdim.

04

Steqanoqrafiya təhlili

4.1 — Binwalk ilə gizli fayl axtarışı

FTP-dən endirdiyim PNG faylının içində əlavə bir fayl gizlədilib-gizlədilmədiyini yoxlamaq üçün binwalk istifadə etdim:

binwalk cutie.png
Qeyd: binwalk faylların içərisində gizlədilmiş və ya əlavə olunmuş məlumatları (məsələn, arxivləri) aşkar etmək üçün istifadə olunan bir Linux alətidir.

Əlavə olaraq, ExifTool ilə faylın metadata məlumatlarına da baxdım — bu bəzən şəklin mənbəyi və ya əlavə qeydlər barədə faydalı ipucu verə bilir:

exiftool cutie.png

4.2 — Gizlədilmiş ZIP-in çıxarılması və parolun sındırılması

Binwalk-un tapdığı ZIP-i şəklin içindən ayırdım:

binwalk -e cutie.png

ZIP-i açmağa çalışdıqda parol tələb olundu. Bunun üçün zip2john ilə hash formatına çevirib, John the Ripper ilə sındırdım:

zip2john cutie.zip > cutie_hash.txt
john --wordlist=/usr/share/wordlists/rockyou.txt cutie_hash.txt

4.3 — Steghide / Stegseek ilə gizli mesajın tapılması

ZIP-in içindən çıxan cute-alien.jpg faylında da gizli məlumat olub-olmadığını yoxladım:

steghide info cute-alien.jpg

Steghide passphrase istədiyi üçün stegseek alətini istifadə etdim. Stegseek eyni prinsipdə işləyir, sadəcə rockyou.txt lüğətindəki parolları avtomatik sınayaraq daha sürətli nəticə verir:

stegseek cute-alien.jpg /usr/share/wordlists/rockyou.txt

Alət arxa planda belə işləyir:

  • stegseek şəklin içində Steghide ilə gizlədilmiş məlumat olub-olmadığını yoxlayır;
  • əgər varsa, rockyou.txt lüğətindəki parolları bir-bir sınaqdan keçirir (dictionary attack);
  • düzgün parolu tapanda onu göstərir və gizlədilmiş faylı avtomatik çıxarır.

Çıxan fayldan james adlı ikinci istifadəçinin adını və SSH parolunu əldə etdim.

05

İlkin giriş — SSH ilə daxil olma

Tapdığım etimadnamələrlə james istifadəçisi kimi SSH üzərindən serverə daxil oldum:

ssh james@<target-ip>

Ev qovluğunda user.txt faylını oxuyub istifadəçi bayrağını (user flag) əldə etdim. Eyni qovluqda Alien_autospy.jpg adlı başqa bir şəkil də var idi (fayl adındakı "autospy" yazılışı otağın öz uydurmasıdır, orfoqrafik səhv deyil).

Şəkli yerli maşınama köçürüb (scp) tərs şəkil axtarışı (reverse image search) etdim. Nəticədə şəklin 1947-ci il Roswell hadisəsi ilə əlaqəli "alien autopsy" görüntüsü olduğunu müəyyən etdim — bu, otağın suallarından birinə cavab verirdi.

06

Privilege Escalation — CVE-2019-14287

Root-a keçmək üçün ilk növbədə james istifadəçisinin sudo ilə hansı hüquqlara malik olduğunu yoxladım:

sudo -l

Adətən gördüyümüz (ALL) ALL əvəzinə burada (ALL, !root) /bin/bash yazılmışdı — yəni james, root istisna olmaqla, istənilən istifadəçi kimi /bin/bash icra edə bilər. Bu qeyri-adi konfiqurasiya bir zəiflik siqnalı idi, ona görə bunu araşdırdım və CVE-2019-14287-ə rast gəldim.

CVE-2019-14287 sudo-nun köhnə versiyalarında olan bir zəiflikdir: sudo istifadəçi ID-ni (UID) yoxlayarkən, UID kimi -1 və ya onun 32-bit unsigned təmsili olan 4294967295 dəyəri verildikdə bunu 0 (yəni root) kimi şərh edir. Nəticədə !root məhdudiyyəti sadəcə fırıldaqla aradan qaldırıla bilir. Bunu belə istismar etdim:

sudo -u#-1 /bin/bash

Bu əmr məni birbaşa root shell-ə apardı və /root/root.txt faylını oxuya bildim.

08

Nəticə və Öyrənilənlər

  • HTTP başlıqları (User-Agent və s.) bəzən tətbiqin davranışını dəyişə bilər — bunları həmişə yoxlamaq lazımdır.
  • Zəif parollar hələ də ən çox rast gəlinən zəiflik vektorlarından biridir; FTP və SSH kimi servislərə brute-force həmişə sınamağa dəyər.
  • Şəkil və digər media faylları gözlə görünməyən əlavə məlumatlar (ZIP, mətn və s.) gizlədə bilər — binwalk, exiftool və steghide/stegseek bu cür təhlillər üçün əvəzsiz alətlərdir.
  • sudo -l çıxışını diqqətlə oxumaq vacibdir — "ALL" əvəzinə qeyri-standart qaydalar (məsələn "!root") görsən, bu adətən konkret, məlum bir zəifliyə işarədir.
  • Köhnəlmiş proqram versiyaları (bu halda sudo) real CVE-lərə açıq qala bilər — sistemləri müntəzəm yeniləmək kritik əhəmiyyət daşıyır.
