Easy SMB FTP NFS Privilege Escalation

TryHackMe — Kenobi Write-up

SMB/NFS enumerasiyası, ProFTPD SITE COPY zəifliyi və SUID/PATH hijacking ilə root əldə etmək

1. Giriş

Kenobi otağı, bir neçə fərqli servisin (SMB, FTP, NFS, SSH) bir araya gətirilməsi ilə real həyatda rast gəlinə biləcək bir "misconfiguration chain" (səhv konfiqurasiyaların zənciri) nümayiş etdirir. Məqsəd: ilkin girişi (initial access) əldə etmək və sonra root səviyyəsinə qədər hüquq yüksəltmək (privilege escalation).

2. Reconnaissance (Nmap Scan)

İlk addım olaraq hədəf sistemdə hansı portların açıq olduğunu görmək üçün Nmap skanı işlədildi:

nmap -sV -sC -p- <target-ip>

Nəticədə 7 açıq port aşkarlandı. Bunların arasında diqqəti çəkən əsas servislər:

PortServisQeyd
21FTPProFTPD
22SSHKey-based giriş dəstəklənir
111NFS/rpcbind/var mount edilə bilir
139/445SMBPaylaşımlar mövcuddur
Termin izahı: -sC bayrağı Nmap-ın standart NSE (Nmap Scripting Engine) skriptlərini işə salır, -sV isə servislərin versiyasını müəyyən edir. Bu skriptlər avtomatik olaraq SMB paylaşımları, NFS export-ları kimi əlavə məlumatları da çıxara bilir.

3. SMB Enumerasiyası

Nmap-ın NSE skriptləri (smb-enum-shares, smb-enum-users kimi) vasitəsilə SMB üzərində istifadəçilər və paylaşımlar araşdırıldı.

Nəticə: 3 paylaşım (share) tapıldı, onlardan biri anonymous girişə açıq idi.

smbclient //<target-ip>/anonymous

Paylaşım daxilində log.txt adlı fayl aşkarlandı və yerli maşına köçürüldü:

get log.txt
Anonymous SMB share: SMB servisinin autentifikasiya tələb etmədən istənilən istifadəçiyə giriş icazəsi verməsi deməkdir. Real mühitdə bu, ciddi konfiqurasiya səhvi sayılır — həssas fayllar heç bir icazə olmadan əldə edilə bilər.

4. FTP və NFS Enumerasiyası

FTP (port 21): ProFTPD servisi işlədiyi aşkarlandı — sonrakı exploitasiya üçün açar rol oynayacaqdı.

NFS (port 111): NFS export-ları yoxlanıldı və /var qovluğunun mount edilə bilən olduğu müəyyən edildi.

showmount -e <target-ip>
NFS export: NFS uzaq bir sistemin fayl sistemini şəbəkə üzərindən "mount" etməyə imkan verir. Əgər /var kimi həssas qovluq düzgün icazələr olmadan export edilibsə, uzaqdan fayllara giriş yaranır — məhz bu otaqda istismar olunan zəiflik budur.

5. ProFTPD Exploit Axtarışı

ProFTPD versiyasına uyğun məlum zəifliklər searchsploit ilə araşdırıldı:

searchsploit proftpd

Nəticə: 4 potensial exploit tapıldı. Diqqət çəkəni SITE CPFR və SITE CPTO əmrləri ilə bağlı zəiflik idi — bu əmrlər server üzərində fayl kopyalamağa imkan verir.

SITE CPFR / SITE CPTO: ProFTPD-nin mod_copy modulunun əmrləridir. SITE CPFR <mənbə> faylın haradan, SITE CPTO <hədəf> isə haraya kopyalanacağını bildirir. Zəiflik ondadır ki, bu əmrlər autentifikasiyasız istifadəçilərə də fayl kopyalamağa imkan verir.

6. Zəifliklərin Zəncirlənməsi — İlkin Giriş

Üç ayrı tapıntı bir-birinə bağlandı: (1) SSH-in key-based girişi dəstəklədiyi, (2) FTP-dəki SITE CPFR/CPTO zəifliyi, (3) NFS vasitəsilə /var-ın mount edilə bilməsi.

FTP-yə qoşulub, id_rsa faylını /var/tmp qovluğuna kopyalamaq:

ftp <target-ip>
SITE CPFR /home/kenobi/.ssh/id_rsa
SITE CPTO /var/tmp/id_rsa

Öz sistemimizdə mount nöqtəsi yaradılıb, /var bağlanıldı:

mkdir /mnt/kenobiNFS
mount <target-ip>:/var /mnt/kenobiNFS
ls -la /mnt/kenobiNFS

Bu əməliyyatdan sonra id_rsa faylı artıq yerli /mnt/kenobiNFS qovluğunda görünürdü. SSH ilə giriş:

chmod 600 id_rsa
ssh -i id_rsa kenobi@<target-ip>

Nəticədə kenobi istifadəçisi kimi ilkin giriş əldə edildi.

Zəncirin əhəmiyyəti: Heç bir tək zəiflik başlı-başına kifayət etmirdi. SSH key-in mövcudluğunu bilmək, onu FTP vasitəsilə köçürmək və NFS vasitəsilə "oğurlamaq" bacarığı ilə birləşdi — real pentesting-də tez-tez rast gəlinən zəifliklərin zəncirlənməsi prinsipi.

7. Privilege Escalation

SUID bitinə malik fayllar axtarıldı:

find / -perm -u=s -type f 2>/dev/null
SUID bit: Bir icra faylına təyin edildikdə, fayl işə düşdüyü zaman onu işə salan istifadəçidən asılı olmayaraq, faylın sahibinin hüquqları ilə icra olunur. Düzgün yazılmayıbsa, hüquq yüksəltmək üçün istifadə oluna bilər.

Axtarışda qeyri-standart SUID fayl aşkarlandı: /usr/bin/menu. İcra edildikdə arxa planda avtomatik olaraq başqa proqramları (məsələn curl) çağırdığı müşahidə olundu.

İstismar üsulu — PATH Hijacking: menu proqramı curl əmrini tam yol göstərmədən çağırdığı üçün, saxta curl faylı yaradıldı:

echo "/bin/sh" > curl
chmod 777 curl
export PATH=/tmp:$PATH

/usr/bin/menu yenidən icra edildiyində, öz saxta curl faylımız (/bin/sh) işə düşdü. menu proqramı root hüquqları ilə işlədiyi üçün, açılan shell də root səviyyəsində oldu.

PATH Hijacking: Bir proqramın çağırdığı əmrin tam sistem yolunu deyil, sadəcə adını istifadə etməsindən yaranan zəiflikdir. Hücumçu öz $PATH mühit dəyişənini manipulyasiya edərək, sistemin əsl proqramı yerinə özününkünü işə saldıra bilər. SUID fayllarda xüsusilə təhlükəlidir.

8. Nəticə və Öyrənilənlər

Enumerasiyanın vacibliyi: Hər açıq portu ayrı-ayrılıqda araşdırmaq, sonda onların birlikdə necə istismar oluna biləcəyini göstərdi.

Zəifliklərin zəncirlənməsi: Tək bir zəiflik kifayət etmədi — üç fərqli tapıntı birləşərək ilkin girişi mümkün etdi.

SUID + PATH Hijacking: "Adi" görünən bir SUID proqramın belə, düzgün yazılmadıqda tam sistem kompromisinə səbəb ola biləcəyini nümayiş etdirdi.

Əldə edilən flag-lar: User flag və Root flag.
