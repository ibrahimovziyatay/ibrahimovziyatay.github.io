NahamStore - Open Redirect Write-Up

Penetration Testing & Vulnerability Assessment Report
Hədəf Tətbiqnahamstore.thm
Zəiflik NövüOpen Redirect
Təhlükə SəviyyəsiMedium
Təhlil MetoduParam Fuzzing & PoC
1. Giriş və Təhlil İcmalı

Bu təhlükəsizlik hesabatı NahamStore hədəf veb-tətbiqində həyata keçirdiyim sınaqlar zamanı aşkarladığım iki fərqli Open Redirect (Açıq Yönləndirmə) zəifliyini əks etdirir[cite: 8]. Open Redirect zəifliyi tətbiqin istifadəçidən aldığı URL parametrlərini lazımi sanitizasiya və validation (doğrulama) mərhələsindən keçirmədən xarici keçidlərə yönləndirməsi nəticəsində yaranır[cite: 8]. Bu zəiflik istifadəçiləri fişinq (phishing) hücumlarına məruz qoymaq üçün istifadə edilə bilər[cite: 8].

2. Open Redirect #1: Arjun Tool ilə Gizli Parameter Analizi

Ana səhifədə HTTP sorğusu vasitəsilə qəbul edilən gizli parametrləri aşkar etmək üçün Arjun parametr fuzzer alətindən istifadə etdim[cite: 8].

Addım 1: Parametrlərin Skan Olunması (Discovery)

user@kali:~$ arjun -u http://nahamstore.thm/ [*] Scanning 0/1: http://nahamstore.thm/ [*] Probing the target for stability [*] Analysing HTTP response for anomalies [+] Extracted 1 parameter from response for testing: q [*] Logicforcing the URL endpoint [✔] parameter detected: q, based on: body length [✔] parameter detected: r, based on: http code [+] Parameters found: q, r

Addım 2: Zəifliyin Yoxlanılması və İstismarı (Exploitation)

  • q parametrini sınaqdan keçirdim, lakin heç bir yönləndirmə davranışı müşahidə olunmadı[cite: 8].
  • r parametrini kənar URL ilə test etdim: http://nahamstore.thm/?r=http://www.google.com[cite: 8]
  • Sorğunu göndərdikdə tətbiq istifadəçini birbaşa xarici google.com saytına yönləndirdi[cite: 8].
3. Open Redirect #2: Əlavə Ünvan Bölməsində Yönləndirmə

İkinci zəifliyi tətbiqin daxili funksionallığını istifadəçi alış-veriş və ünvan əlavəetmə (Address Book) prosesini təhlil edərkən tapdım[cite: 9].

Addım 1: İstifadəçi Axını və Parametrin Təyini

Ana səhifədən istənilən bir məhsul seçib səbətə əlavə etdim (Add to basket)[cite: 9]. Səbət bölməsində Add to another address düyməsinə kliklədim[cite: 9]. Səhifənin URL ünvanında redirect_url parametrinin işləndiyini müşahidə etdim[cite: 9]:

http://nahamstore.thm/account/addressbook?redirect_url=...

Addım 2: Payload-un Tətbiqi və Yönləndirmə

URL-dəki redirect_url parametrinin qiymətini xarici URL ilə dəyişdirdim[cite: 9]:

http://nahamstore.thm/account/addressbook?redirect_url=http://www.google.com/

Ünvan məlumatlarını doldurub "Add Address" düyməsini sıxdıqda tətbiq ünvanı yadda saxladı və dərhal təyin etdiyim google.com ünvanına yönləndirdi[cite: 9].

4. Potensial Risk və Təsir (Impact)
  • Sosial Mühəndislik (Phishing): Hücumçular rəsmi domendən istifadə edərək etibarlı görünən linklər hazırlayır və istifadəçiləri saxta daxilolma (login) səhifələrinə yönləndirərək şifrələrini ələ keçirirlər[cite: 9].
  • OAuth Token Sızması: Tətbiq OAuth protokolu istifadə edirsə, bu zəiflik vasitəsilə avtorizasiya kodları kənar serverlərə sızdırıla bilər[cite: 9].
5. Təhlükəsizlik Tövsiyələri (Remediation)
  • Nisbi URL (Relative Path) İstifadəsini Məcbur Etmək: Yönləndirmə parametrlərində yalnız daxili yollara (məsələn, /account/addressbook) icazə verilməli, http:// və ya https:// ilə başlayan xarici ünvanlar bloklanmalıdır[cite: 9].
