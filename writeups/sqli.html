NahamStore Write-up — SQL Injection

Klassik (union-based) və Blind SQL Injection zəifliklərinin aşkarlanması

Bu sənəd "NahamStore" tətbiqində aşkarlanmış iki fərqli SQL Injection zəifliyinin araşdırılması prosesini əks etdirir: birincisi klassik (union-based), ikincisi isə blind SQL injection nümunəsidir[cite: 21].

1-ci Flag (Union-Based SQLi)
  1. /product?id=' sorğusu göndərildikdə server birbaşa raw MySQL sintaksis xətasını geri qaytardı[cite: 23]:
    You have an error in your SQL syntax; check the manual... near " LIMIT 1"
  2. Zəifliyi təsdiqləmək üçün id=-1 union select 1,2,3,4,5-- payload-u istifadə olundu ("2" və "4" reflected sütunlar idi)[cite: 23].
  3. Verilənlər bazası adını tapmaq üçün id=-1 union select 1,database(),3,4,5-- göndərildi və bazanın adının nahamstore olduğu müəyyən edildi[cite: 23].
  4. Prosesi sürətləndirmək üçün sqlmap aləti istifadə edildi[cite: 23]. sqli_one cədvəlindən flag çıxarıldı[cite: 24].
1-ci Flag: {d890234e20be48ff96a2f9caab0de55c}[cite: 24]
2-ci Flag (Blind SQL Injection)
  1. POST /returns endpoint-indəki forma sahələri (order_number, return_reason, return_info) araşdırıldı[cite: 24, 25].
  2. order_number sahəsinə * işarəsi qoyularaq sqlmap alətinə xüsusi bu parametr hədəf göstərildi[cite: 25]:
    sqlmap -r request.txt -p order_number
  3. Blind SQLi vasitəsilə sqli_two cədvəlindən ikinci flag əldə edildi[cite: 25, 26].
2-ci Flag: {212ec3b036925a38b7167cf9f0243015}[cite: 26]
Nəticə və Tövsiyələr

Nəticə: Birinci zəiflik birbaşa xəta mesajı verdiyi üçün Union-based, ikinci zəiflik isə cavabda xəta görünmədiyi üçün Blind SQL Injection idi[cite: 26].

Tövsiyələr: Bütün istifadəçi girişləri parametrləşdirilmiş sorğular (prepared statements) vasitəsilə emal edilməli, bazanın xəta mesajları istifadəçiyə göstərilməməlidir[cite: 26].
