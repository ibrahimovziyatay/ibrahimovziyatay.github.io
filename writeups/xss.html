SECURITY WRITE-UP

NahamStore Write-up

Task 4 — Cross-Site Scripting (XSS) Zəifliklərinin Aşkarlanması

Bu sənəddə NahamStore tətbiqi üzərində aşkar olunmuş Reflected və Stored XSS zəifliklərinin manual kəşfiyyat addımları və Arjun + Dalfox alətləri ilə avtomatlaşdırılması təhlil olunur.

1. Reflected XSS Endpoint-i
Sual: XSS-ə qarşı həssas olan endpoint-in parametrlərlə birlikdə URL-ini qeyd edin.
  1. marketing.nahamstore.thm alt domenində reflected (əks olunan) tipli XSS zəifliyi araşdırıldı.
  2. Səhifədə bir login forması aşkar edildi. Test məqsədilə test123 istifadəçi adı və test123@123 e-poçt ünvanı ilə giriş cəhdi edildi, lakin heç bir nəticə alınmadı.
  3. Ünvan sətrində URL-encode edilmiş bir sətir müşahidə olundu. Sistemin bu dəyərə necə reaksiya verdiyini öyrənmək üçün həmin sətir təsadüfi simvollarla dəyişdirildi.
  4. Dəyişiklikdən sonra səhifənin cavabında error adlı bir parametrin qaytarıldığı müşahidə edildi.
  5. Bu parametrin XSS-ə qarşı həssas ola biləcəyi ehtimal edildiyi üçün <script>alert(1)</script> payload-u həmin parametrə yerləşdirildi.
  6. Nəticədə brauzerdə "1" mesajı olan alert pəncərəsi çıxdı, bu da endpoint-in XSS zəifliyinə malik olduğunu təsdiqlədi.
2. Stored XSS yaradan HTTP Başlığı
Sual: Stored (saxlanılan) XSS yaratmaq üçün hansı HTTP başlığından istifadə oluna bilər?
  1. nahamstore.thm əsas səhifəsinə keçid edildi.
  2. İstənilən e-poçt və parol ilə qeydiyyatdan keçildi, ardından sistemə daxil olunaraq "Address Book" bölməsinə keçildi.
  3. Bu bölmədəki forma dolduruldu və yeni bir ünvan yaradıldı.
  4. "Item" bölməsinə keçilərək yaradılmış ünvana baxıldı. Ünvana klikləndikdə səhifədə User-Agent HTTP başlığının əks olunduğu görüldü.
  5. Burp Suite vasitəsilə HTTP sorğusu tutuldu və User-Agent başlığına sadə bir XSS payload-u yerləşdirildi. Test uğurlu oldu və payload icra olundu.
Cavab: User-Agent
3. Məhsul Səhifəsində HTML Taqı
Sual: Məhsul səhifəsində XSS-in icra olunması üçün hansı HTML taqının escape edilməsi lazımdır?
  1. Əsas səhifədən istənilən məhsulun səhifəsinə keçid edildi.
  2. URL-də name parametrinin ötürüldüyü müşahidə olundu.
  3. Bu parametrə <script>alert(1)</script> payload-u əlavə edildi, lakin script icra olunmadı.
  4. Səbəbi müəyyən etmək və bypass yolunu tapmaq üçün brauzerin "Inspect" funksiyasından istifadə edildi.
  5. Aşkar edildi ki, daxil edilən mətn <title> taqının içərisinə yazıldığı üçün script icra oluna bilmir.
  6. Bunu keçmək üçün payload-un əvvəlinə </title> əlavə edilərək taq bağlandı və alert pəncərəsi çıxdı.
Cavab: title
4. JavaScript Dəyişəni
Sual: XSS-in icra olunması üçün hansı JavaScript dəyişəninin escape edilməsi lazımdır?
  1. Əsas səhifədə yerləşən məhsul axtarış (search) sahəsindən istifadə edilərək müxtəlif dəyərlər daxil edildi və sistemin reaksiyası izlənildi.
  2. Daxil edilən dəyərin search adlı parametr vasitəsilə ötürüldüyü müəyyən edildi.
Cavab: search
5. Əsas Səhifədə Gizli Parametr
Sual: Mağazanın əsas səhifəsində XSS zəifliyi yaradan gizli parametr hansıdır?
Cavab: q
6. Returns Səhifəsində HTML Taqı
Sual: Returns (geri qaytarma) səhifəsində XSS-in icra olunması üçün hansı HTML taqının escape edilməsi lazımdır?
  1. "Returns" səhifəsinə keçid edildi.
  2. "Orders" bölməsində sifariş nömrəsi daxil edildi.
  3. Səhifədə "Return Information" adlı sahə aşkar edildi və <script>alert(1)</script> sınandı, lakin işləmədi.
  4. "Inspect" vasitəsilə daxil edilən mətnin <textarea> taqının daxilində olduğu müəyyən edildi.
  5. Bunu keçmək üçün </textarea> əlavə edilərək taq bağlandı və alert pəncərəsi icra olundu.
Cavab: textarea
7. Səhifənin H1 Taqının Dəyəri
Sual: Sorğu edilən URL-i istifadə edərək XSS yaradan səhifənin H1 taqının dəyəri nədir?
Cavab: page not found
8. Mağazada Digər Gizli Parametr
Sual: Mağazada XSS zəifliyi yarada biləcək digər gizli parametr hansıdır?
Cavab: discount

Ümumi Nəticə

NahamStore platforması üzərində aparılan test zamanı çoxsaylı Cross-Site Scripting (XSS) zəiflikləri aşkar edilmişdir. Zəifliklər həm reflected, həm də stored formada özünü göstərmişdir: error, search, q və discount kimi URL parametrləri, eləcə də User-Agent HTTP başlığı istifadəçi tərəfindən idarə oluna bilən və server tərəfindən lazımınca təmizlənməyən (sanitize edilməyən) giriş nöqtələri olmuşdur. Bundan əlavə, title və textarea HTML taqlarının düzgün escape edilməməsi payload-un müvafiq taqı bağlayaraq (</title>, </textarea>) icra sahəsindən çıxmasına və zərərli JavaScript kodunun işə düşməsinə imkan yaratmışdır. Bu, tətbiqin istifadəçi girişini kontekstə uyğun şəkildə kodlaşdırmadığını (context-aware output encoding) və bunun nəticəsində sessiya oğurluğu, fişinq və digər client-side hücumlara açıq olduğunu göstərir.

Avtomatlaşdırılmış alətlərlə (Arjun + Dalfox) XSS Aşkarlanması

Yuxarıdakı zəifliklər əl ilə (manual) test zamanı tapılsa da, oxşar parametrlər eyni prosesi Arjun və Dalfox alətlərinin birgə istifadəsi ilə avtomatik şəkildə də aşkar etmək mümkündür:

  • Arjun: Endpoint-də gizli, sənədləşdirilməmiş HTTP parametrlərini (GET/POST) brute-force üsulu ilə tapan alətdir. Yuxarıdakı q və discount kimi gizli parametrlər bu alətlə aşkarlanır.
  • Dalfox: Tapılmış parametrləri avtomatik olaraq müxtəlif XSS payload-ları ilə sınayan, əks olunma nöqtəsini (reflection) təhlil edən və real XSS zəifliyini təsdiqləyən skanerdir.
Nümunə: Mağazanın Əsas Səhifəsi Üzərində Tətbiq

Addım 1: Arjun ilə gizli parametrlərin tapılması

Bu əmr saytın əsas səhifəsinə yüzlərlə mümkün parametr adı ilə sorğu göndərir və serverin cavabında dəyişiklik yaradan parametrləri (məsələn, q və discount) aşkar edərək nəticəni fayla yazır.

bash - Arjun Parameter Discovery
user@kali:~$ arjun -u http://nahamstore.thm/ -oT arjun_params.txt
[+] Scanning http://nahamstore.thm/ ...
[+] Found parameter: q
[+] Found parameter: discount
[+] Saved results to arjun_params.txt

Addım 2: Tapılan parametrləri Dalfox-a ötürərək XSS skan etmək

Dalfox hər bir parametrə ardıcıl olaraq müxtəlif XSS payload-ları yerləşdirir, cavab HTML-ində bu payload-un necə əks olunduğunu analiz edir və avtomatik olaraq işləyən (verified) XSS zəifliyini bildirir.

bash - Dalfox XSS Scanner
user@kali:~$ dalfox url "http://nahamstore.thm/?q=FUZZ&discount=FUZZ" --deep-domxss
[*] Injected payloads into query parameters...
[POC] [GET] http://nahamstore.thm/?q=%3Cscript%3Ealert(1)%3C%2Fscript%3E&discount=1 Triggered

Beləliklə, Arjun gizli parametrləri aşkar edən "kəşfiyyat" mərhələsini, Dalfox isə tapılan parametrlərin real şəkildə istismar oluna bilən (exploitable) XSS zəifliyi olub-olmadığını yoxlayan "doğrulama" mərhələsini avtomatlaşdıraraq analizin müddətini dəqiqələrə endirir.
